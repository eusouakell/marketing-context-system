# Context domains

This index describes a reusable public architecture. No proprietary brand, campaign, customer or company evidence is included.

| Domain | Canonical knowledge to supply | Boundary |
|---|---|---|
| Brand | Positioning, message hierarchy, voice, terminology | Derived campaigns are examples, not authority |
| Market | Dated observations, sources and scope | Separate observation from strategic decision |
| Audience | Approved ICP, roles, needs and buying context | Do not invent missing audience facts |
| Offer | Approved offer architecture and constraints | Changes require human decisions |
| Content | Editorial and channel constraints | Keep channel artifacts separate from strategy |
| Proof | Evidence records and claim mappings | Check publication permission and freshness |
| Go-to-market | Approved commercial decisions | Separate current state from historical decisions |
| Governance | Authority, permissions and publication rules | Human gates cannot be silently bypassed |

Create domain files only with public or explicitly authorized knowledge. For each canonical record, capture source, authority, version/date, status and publication scope. Use [SYSTEM-SPEC.md](../SYSTEM-SPEC.md) and [the example bundle](../examples/task-context-bundle.md) to route only what the task needs.
